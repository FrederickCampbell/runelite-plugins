# Farming Helper v1.01 audit

## Result

The v1.0 baseline is [2a86531](https://github.com/FrederickCampbell/runelite-plugins/commit/2a86531). The release removes 1,115 of 8,070 maintainable production Java lines (13.8%). A 20% reduction would require another 499 lines. The largest individual reductions were the physical catalog (198 to 60), waypoints (296 to 156) and run ordering (247 to 135).

| Production subsystem | v1.0 | v1.01 | Net lines removed |
| --- | ---: | ---: | ---: |
| Navigation and travel | 965 | 699 | 266 |
| Physical patches and live verification | 1,425 | 1,074 | 351 |
| Crop data, allocation and stock | 855 | 553 | 302 |
| Run engine, care and supplies | 2,217 | 2,117 | 100 |
| Bank, vault and item overlays | 1,198 | 1,129 | 69 |
| Preferences and selection | 282 | 263 | 19 |
| Sidebar and presentation | 1,128 | 1,120 | 8 |
| **Total** | **8,070** | **6,955** | **1,115** |

Counts include comments and blank lines in tracked production Java. The farming-state adapter is included. Seven inherited registry and decoder files contribute 3,774 additional lines to both versions and are byte-identical. Tests, fixtures, resources and documentation are excluded. Including inherited files, production Java went from 11,844 to 10,729 lines.

## Regressions and checks

| v1.0 finding | v1.01 behavior and regression evidence |
| --- | --- |
| A native vault rebuild could replace children or set the native scroll height after the compact view had already been applied. Direct calls to the inner contents builder could bypass the old wrapper hook. | Restore the previous projection before native script work. Coalesce a layout pass after the script stack completes, re-read native slots and viewport geometry, and check for later native header or scroll changes. Tests cover nested and direct builds, a partial withdrawal, depletion, redeposit, a new sapling section and restoring native positions and scroll. |
| Preparation held the initially selected destination, and could continue routing after supplies were gathered. | Recompute the destination from observed physical shortages and the original preparation origin. A run-level test opens both stores, changes the observed supply source, gathers the items and verifies the route disappears. |
| A preparatory tree item could inflate the carried sapling count. | Allocation may reserve a seed or seedling. The checklist reports actual saplings carried, preparatory materials and physical withdrawals separately. The planting step asks for a plantable sapling. |
| Changing a crop-type default left previously rendered species controls stale. | The preferences page refreshes dependent controls and preserves its scroll position. Run, patch, species and type overrides share one precedence rule. |
| Teleport recommendations and itineraries used different labels for the same physical site. | Both use the itinerary site identity. Coverage exercises every registered farming and birdhouse stop against the shipped transport destinations. Anglers’ Retreat retains its boat leg. |
| A patch absent from the original actionable list could be skipped before a new observation. | Newly actionable patches join the remaining itinerary. An existing stop keeps its position, and an explicitly skipped crop type keeps its skip when it unlocks. |

## Consolidation and performance

- Removed the unused spatial optimizer, multi-target route refinement and probes, superseded itinerary tables, old sapling planning methods and unused supply and navigation entry points. The surviving route planner is exercised by the original itinerary scenarios.
- The inherited registry supplies physical plot names. A baseline fixture verifies the order, saved keys, destinations, varbits and gardeners of all 111 farming and birdhouse stops. A separate check verifies all 1,528 original type-to-object associations and the gaps between IDs.
- Each of the 81 crops defines its plantable ID, planting quantity, XP components and protection costs together. A release fixture verifies every XP input and item definition. Protection costs retain their independent audited table test. Native seed and seedling aliases share a single lookup.
- The run uses one outcome per included patch and a separate live evidence tracker. Preparation, resupply and active guidance have explicit phases. Tests exercise preservation, contracts, skips, same-character hopping, logout and route ownership.
- Spawns and despawns maintain one farming-object collection. Highlighting, approach selection, disease checks and special live verification use it. Exact geometry, varbit, transform and world-view checks remain in place. Object matches are reused within a tick and invalidated by scene and variable changes.
- Container events and store visits invalidate physical totals. Allocation, crop ranks, teleport eligibility and active Bank Tags shelf membership reuse unchanged inputs. Quest states are read once per unique quest in an access poll. Timers, unlocks and live farming state still update during runs.
- The sidebar compares immutable guide snapshots directly and updates existing rows when their structure permits. Shared controls handle preference dropdowns, information rows, checkboxes and scroll restoration. The sample active-guide image matches the v1.0 PNG byte for byte.

## Validation and remaining work

The JDK 21 Gradle clean, test and build completed with 170 passing tests across 48 test classes and produced the Java 11-targeted JAR. No runtime dependency, game-input API or additional pathfinder was added. The pending Plugin Hub submission was outside the release changes.

The main plugin remains 1,223 lines, including the ordering of current-patch observations, disease interruptions and supply decisions. The sidebar remains 867 lines across distinct player screens. Native vault geometry and late widget writes still require explicit ownership and fallback logic. These are the main remaining opportunities for reduction. No live-client CPU or frame-time benchmark was collected.

Final in-game checks are the vault transaction matrix, Bank Tags remembered-tab behavior, third-party route ownership and specialty travel, and nearby flowers, bins and disease interruptions. The [live acceptance checklist](../PLUGIN_HUB_REVIEW.md) gives the specific actions.
