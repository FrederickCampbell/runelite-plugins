# v1.07.4 GUI and code consolidation audit

Baseline: 86d5d11444d7a9b86b35b69c5df7c5d461532369 (v1.07.3). Objective: reduce actual duplication and needless rebuilding, not compress formatting, move lines to extra classes, or discard functionality. No native widget or input automation changes.

## Implemented

- Stable Swing priority rows: actions resolve the current rank by crop name, existing rows are reordered rather than rebuilt, and the add dropdown stays mounted. Removing a row removes only that row. The same shared theme, icons, names and preference keys remain. Patch enable toggles update their count locally. Same-session structural guide updates retain the toolbar; a new session resets it.
- Shared UI primitives: disclosure icon/accessibility state, expandable section-body removal, native action buttons, vertical panels and escaped HTML. Existing native layout, wrapping, inline help, scroll anchoring and pinned preparation controls remain. No global focus management.
- Shared planner inputs: one local crop region scan serves disease and watering. Selection/eligibility checks are shared, the per-update eligible subset also serves staged birdhouse presentation. Disease intentionally remains independent of selected runs; optional watering continues to respect its existing eligibility and ordering. Existing per-update observation and allocation caches remain.
- Allocation: reserve contract, committed crops, lilies and patch overrides in the same order. Read each remaining override once and build one preferred/XP list per crop type; retain explicit guide-anyway fallback when stock is exhausted. Native contract metadata indexed once. Sapling stages counted in one pass.
- One initial/resupply bank-choice implementation; one living-produce decoder path; shared patch-selection helper. Avoid recalculating birdhouse direction for each route block. Seed-box pickup message parsing consolidated with same native-vs-chat precedence.
- Retained old public preference identifiers, all crop/patch data, native bank and vault behavior, optional Shortest Path, all run stages, overlays and safeguards from v1.06.1–1.07.3.

## Deliberately not merged or removed

The existing separately testable crop, stock, guide state and route helpers are not interchangeable. The main update method still orchestrates distinct disease, ordinary care, seedless, specialty, preparation, and presentation phases. Collapsing those into one flag or doing a single destructive pass would alter order/precedence. No arbitrary LOC quota. GUI page transitions still reconstruct structural content where inputs genuinely change; patch search and guide item quantity updates retain their existing stable controls. A full native vault renderer rewrite, speculative removal of unused-looking compatibility paths, or replacing the inherited decoder would carry disproportionate regression risk. Further improvements require a live-client profile and acceptance results, not a blind rewrite.

## Validation

Regression suite includes existing native storage, overlay, lifecycle, seedless, contract, and UI resizing tests. New coverage checks control identity after reorder/toggle and same-run header rebuild, per-type priority reads, explicit fallback, initial/resupply selection and shared stage accounting. Static code review and CI do not establish live FPS, keyboard focus retention under all desktop conditions or Plugin Hub approval.
