# v1.07.2 storage audit

Baseline: aa5cc0a5d3fb1738645633a7ee8dc6cdc74b9846 (v1.07.1). Scope: PhysicalStock, StockSnapshot, SeedBoxStock, FarmingHelperPlugin storage and menu/event paths, ActiveRunBank, BankShelfLayout, SeedVaultViews, VaultGrid, VaultRanking, TreePreparation, Preparation, SeedChoices, SupplyOrder, GuidePresentation, CuratedBank, relevant regression fixtures. Static source review plus CI, not a live client trace.

## Verified findings and remediation

| Area | Finding | Change |
| --- | --- | --- |
| Native observations | A null item array or unresolved item definition looked like an empty/partial successful snapshot. | Strict storage reads publish atomically only after a complete decode; inventory reads still retain known physical items. |
| Profile state | Observation timestamps were reset on profile load; events could reach cached state before the next regular sample. | Persist successful per-profile timestamps; load the current profile before stock reads and events; discard pending observations on profile changes. |
| Close races | A deferred sample could miss the final withdrawal if the interface closed first. | Capture a complete visible storage event, reconcile at the next sample even if the interface closed. |
| Placeholders | Physical counts and layout IDs must never mix. | Publish placeholder IDs only after successful full decode; native placeholders remain visual only. |
| Seed box | Any menu click discarded the pending action. | Keep pending actions through ordinary clicks; overlap or unavailable storage invalidates uncertain counts rather than inventing quantities. |
| Seed box | Check messages finalized after one tick; native and chat pickup observations could double-count across adjacent ticks. | Wait for a two-tick quiet window; discard checks invalidated by mutations; account for matching native increments in the adjacent tick. Native order is marked uncertain on box UI actions. |
| Seed box | Missing or malformed native item array could be accepted or throw. | Validate snapshot shape and recognized seed IDs before replacement. Cached historical counts are never promoted on login. |
| Vault | Unsafe sections could be partially hidden before safety validation; header-only refresh detection missed replacement child arrays. | Skip unsafe sections completely; track item, label, header and divider arrays and applied properties. |
| Vault | Left-panel restoration could overwrite a newer native scroll height. | Restore only the height actually applied by the helper. |
| Bank Tags | Closing/reopening inside a game tick could retain a stale layout registration. | Release registration on bank-close event and clear inactive service references. |
| Arithmetic | Duplicate stacks, tree aliases and carried/bank totals could overflow. | Saturating count addition and widened comparisons. |

## Preserved behavior

Seedless policies, crop preference order, contract allocation, raw seed/seedling/sapling distinction, existing bank shelf and withdrawal placeholders, carried equipment canonicalization for display only, manual browsing, native item IDs, indices, quantities and actions. No input automation, dependency changes, game actions or independent pathfinding.

## Remaining limits / live acceptance

Closed-box chat and container events lack a transaction ID. Adjacent matching native increments are treated as one observation, but real client timing must be exercised; ambiguous overlapping actions intentionally reduce confidence. The tracker still cannot discover changes to unopened storage made while disabled or on another client. Historical bank/vault counts remain advisory and the user can refresh them. A genuinely unsupported vault grid remains native rather than forcing compactness. Test fast close, delayed inventory packets, repeated identical pickups, reorder, direct planting from the box and loose seeds, changes while the UI is closed, profile switches, each vault category/resize/search and native withdrawal quantities. The native client, Bank Tags and optional integration lifecycle require live verification. No claim of reviewer approval or measured performance.
