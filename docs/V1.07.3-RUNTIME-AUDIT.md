# v1.07.3 runtime and code-consolidation audit

Baseline: b267bbf87a8b7d365cdfb91f69fdd099f6d6676a (v1.07.2). Review: plugin startup/shutdown, profile and game-state events, run mutations, sidebar publication, navigation message state, bank shelf, item/patch overlays, stock and allocation invalidation, scene ownership, icons and existing tests. Cross-checked RuneLite PluginManager, GameEventManager, ClientThread, EventBus and Shortest Path PluginMessageHandler/Targets. Static audit and regression suite; no live profiling.

## Correctness and performance findings

| Finding | Remediation |
| --- | --- |
| RuneLite starts/stops plugins on EDT, but prior teardown touched game state on EDT. | Queue client-side initialization/teardown in order; keep Swing lifecycle separate. |
| Queued plugin/config/profile callbacks could execute after re-enable. | Lifecycle-guarded client dispatch and atomic run session; central run-action gate checks current profile. |
| Delayed sidebar views could apply to a different panel or older state. | Capture actual panel and session; discard superseded immutable views. |
| Legacy Shortest Path clear could clear a personal route. | Require an exact currentTarget response with no foreign config overrides; expire pending releases. |
| Request IDs repeated when a new bridge was constructed. | Process-unique atomic request sequence; ignore unmatched messages. |
| Duplicate destination and availability state. | Single displayed point and bridge-enabled state; remove duplicate begin/reset call. |
| Unrelated Shortest Path messages invalidated transport lookup. | Dispatch only supported, matched responses on the client thread. |
| Rendered inventory item rebuilt a temporary ID array. | Scan the existing native item array directly, with null/slot checks. |
| Scene spawn repeatedly fetched known object definitions; despawned sub-world views could retain objects. | Known ID fast path, scene-local classification cache, remove objects from unloaded world views. Native scene replay remains the source. |
| Item icons accumulated throughout a run. | Keep only current guide icons; clear on end/disable. |
| Bank shelf reconciled unchanged layout every game tick and could retain stale native registration after injector swap. | Reconcile only changed inputs; preserve manual browsing; reset registration on service replacement. |
| Widget load and game tick independently sampled storage. | Existing game-tick sampler owns observation; preserve event capture from v1.07.2. |
| Run preference setters immediately recalculated preferences again inside update(). | One shared refresh inside update, including during hopping. |

## Consolidation opportunities for v1.07.4

Do not target arbitrary line counts or change public behavior. Use the same maintained-Java baseline and compare both file-level and actual responsibility counts.

1. FarmingHelperPanel: largest UI duplication is repeated page/control construction and per-screen state restoration. Prefer stable native components and shared rows; preserve search field, selection, pinned controls, guide scroll, all existing preferences and accessibility. No global focus or input APIs.
2. FarmingHelperPlugin.update(): numerous independent passes over patches and derived stock. Make one per-update observation and one eligible-selection collection reusable by planning, care, stats, preparation and presentation. Existing observation and allocation caches already eliminate some duplication; don't add a second planner or duplicate stock model.
3. Guide state: audit current/activeCrop/activeCareOnly/activeClearOnly/phase/progress transitions together before collapsing flags. Do not remove separate clear-only, preservation, disease or birdhouse state merely to shorten source.
4. Native storage views: use existing ownership checks for all native widget restoration, retain conservative fallback. Avoid abstracting bank/vault into a shared renderer: their native semantics differ.
5. Configuration: repeated reads and default handling can be grouped only where invalidation is reliable. Keep global defaults and transient overrides separate. Do not cache live quest/diary/crop state indefinitely.
6. Existing small pure classes (StepItems, GuidePresentation, RunProgress, VaultGrid, SeedChoices) are useful independently testable logic, not an automatic consolidation target. Remove actual unused code only after reference search and tests.
7. Keep imported decoder/registry and public attribution unchanged unless correcting a verified state bug; avoid rewriting data tables to chase LOC.

## Remaining constraints

Shortest Path has no exclusive owner token or conditional-clear transaction. An identical unmodified destination cannot prove ownership; there is a race between the read and clear. Legacy integrations without replies, or plugin disable after bus unregistration, can leave a visible route: manual clear is safer than removing another route. Native scene replay is asynchronous; verify rapid disable/re-enable in the live client. No measured CPU, FPS, heap, or allocation rates. Game ticks still intentionally reevaluate access periodically because quest/diary/Sailing unlocks can change without a Farming level event. Full update recomputation remains a target for profiling and consolidation, not an unmeasured rewrite.
